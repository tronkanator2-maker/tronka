# Мир моделей — Telegram-бот

Telegram Bot API, Bun, PostgreSQL, Railway. Telegram Mini App **не используется**.

## Реализовано в текущем техническом MVP

- Анкета пользователя с разбором текста, редактированием по одному полю и фото (до 5).
- Публикация пользовательских заявок, фильтры, рассылка, подбор анкет и остановка поиска.
- Отклики и приглашения, подтверждение взаимодействия, отзывы после проверки результата сотрудничества, ответы на отзывы.
- Настраиваемые владельцем лимиты: по умолчанию 1 активная собственная заявка без подписки, 1 отклик и 1 приглашение в неделю по Москве; 5 уникальных заявок и 3 уникальные анкеты за день для бесплатного доступа. При остановке заявки её место освобождается, повторный просмотр карточки не расходует новую квоту.
- Основа одноразового 15-дневного пробного периода с привязкой к подтверждённому телефону. Код напоминаний за 3 и 1 день с отпиской подготовлен, но отключён до подключения настоящих платежей.
- Приём сообщений из источников, доступных боту, с разбором роли/города, первичной модерацией, проверкой дублей и стоп-листом контактов.
- Жалобы, тикеты, переписка с поддержкой через оператора, кабинет модерации.
- Реферальные ссылки и отслеживание переходов. **Бонусы не начисляются до подключения платежей.**
- Версионирование юридических документов, SHA-256 и аудит согласий.
- Веб-интерфейс владельца с входом по паролю, необязательным до настройки секретного ключа вторым фактором TOTP, ограничением попыток, изменяемыми лимитами, справкой и управлением источниками.
- Контрольный Docker build и автоматические регрессионные тесты перед релизом.

## Примеры анкет и заявок

В каталоге и поиске заявок показываются вымышленные примеры, когда реальных результатов нет. Примеры не сохраняются в базу как участники или объявления. На карточке-примере заявки кнопка отклика показывает будущий сценарий; на настоящих заявках работает реальный отклик с текстом, решением заказчика и перепиской после принятия. В списке примеров есть переход к созданию собственной заявки. Подключённый Telegram-бот: `@ann_agensy_bot` (проверено методом `getMe` Telegram Bot API). **Не путать со старым `@world_mdbot`.**

## Юридические разделы для презентации

`/documents` показывает страницы-заглушки для шести обязательных документов, если утверждённого текста ещё нет. Каждая заглушка отмечена как неюридическая и не записывается в таблицу опубликованных документов. Поэтому `legal_documents_approved=false` остаётся правильным результатом проверки. Для публичного запуска нужно заменить заглушки утверждёнными текстами и только затем выключать `TEST_MODE`.

## Важно: перед публичным запуском

1. Юрист и владелец должны утвердить и опубликовать документы (включая отдельные согласия), затем отключить тестовый режим. До этого production-среда остаётся открытой для проверки функций и не готова к публичному набору пользователей.
2. Установить сильный `ADMIN_PASSWORD` и `ADMIN_IDS` в Railway. Админка входит по паролю и ограничивает частые попытки входа.
3. Добавить бота в Telegram-каналы/чаты с доступом к сообщениям. Обычный Bot API не может самостоятельно находить и читать историю произвольных чатов; для полной функции сбора 71 источника нужен отдельный клиент MTProto, легитимный доступ и тесты лимитов.
4. Подключить внешние платежи и реальные подтверждения личности/семьи через ЕСИА. Сейчас никаких банковских операций или верификации паспорта не производится.
5. Проверить реальные пользовательские сценарии в Telegram на тестовой группе и пройти юридическую/безопасностную приёмку.

## Отдельный коллектор источников

Подготовлены `collector.ts`, `Dockerfile.collector` и `COLLECTOR_SETUP.md`. Они используют отдельный сервис с доступом к той же PostgreSQL; чтение Telegram возможно только для источников, доступных авторизованному аккаунту. Не добавляйте строку MTProto-сессии в GitHub. Сам коллектор **ещё не развёрнут** — отсутствуют действительные `TG_API_ID`, `TG_API_HASH`, `TG_STRING_SESSION`. Источник не подключается, если найден риск несовершеннолетних в откровенных объявлениях: он идёт на ручную проверку. Отдельные тесты и авторизованный доступ обязательны перед запуском.

## Конфигурация Railway

`BOT_TOKEN` — Telegram Bot API token; `WEBHOOK_SECRET` — проверка Telegram secret-token header;
`PUBLIC_URL` — публичный HTTPS адрес; `DATABASE_URL` — PostgreSQL;
`BOT_USERNAME` — имя бота без `@`; `REGISTRATION_ENABLED=false` до приёмки; `TEST_MODE=false` для публичного запуска только после публикации и утверждения документов;
`ADMIN_IDS` — список Telegram ID владельца/модераторов через запятую;
`ADMIN_PASSWORD` — пароль веб-админки;
`PHONE_HASH_PEPPER` — ключ хеширования уникальности пробного периода.
`ADMIN_TOTP_SECRET` — необязательный секрет TOTP владельца, включает обязательный одноразовый код из приложения-аутентификатора при входе; хранить только в Railway.
`TRIAL_REMINDERS_ENABLED` и `PAYMENTS_ENABLED` — обе переменные должны быть `true`, а `TEST_MODE` — `false`, чтобы начать отправку напоминаний о завершении пробного периода. Не включайте их до интеграции настоящего эквайринга.

Код не должен содержать значения токенов, паролей или ключей.

## Маршруты

`GET /health` — проверка базы;
`POST /webhook` — защищённый секретом webhook;
`GET /documents`, `GET /documents/:slug` — опубликованные документы или явно помеченные страницы-заглушки для презентации;
`GET /admin` — панель управления (без `ADMIN_PASSWORD` возвращает 503).

## Качество и приватность

`bun build` и набор регрессионных тестов запускаются при сборке Docker-образа. Telegram/webhook-запросы обрабатываются с защитой от повторов; массовая рассылка использует очередь PostgreSQL и обработку порциями. Реализованы `/mydata`, `/deleteaccount`, отмена операции и повторное согласие на новые версии документов. Текущие Railway production-переменные включают `TEST_MODE=true` и `REGISTRATION_ENABLED=true`; публичный запуск требует опубликованных документов и `TEST_MODE=false`. Категории 18+ скрыты до отдельного выбора совершеннолетним пользователем.

## Текущие ограничения

Требования ТЗ выполнены **частично**. В частности не подключены:
- MTProto-коллектор (требует легитимной сессии и ключей владельца).
- Платёжный провайдер и возвраты.
- Проверка личности, статуса и представителя несовершеннолетнего через ЕСИА или иной согласованный источник.
- Расширенная финансовая аналитика и некоторые роли/разделы админ-панели.

Основные пользовательские сценарии уже доступны в боте. Регистрация сейчас открыта в тестовом режиме; это конфигурация для презентации и проверки, а не для публичного набора реальных пользователей. Перед выпуском нужно пройти сквозную приёмку на двух Telegram-аккаунтах и включить только те интеграции, для которых предоставлены утверждённые условия и ключи.
